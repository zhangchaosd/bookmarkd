## 中文

新增只读集成令牌，供可信的服务端程序（例如个人主页）读取收藏。

- 在服务器上用 `bookmarkd token create <名称>` 生成令牌，只显示一次；`bookmarkd token list` 查看名称、创建与最近使用时间，`bookmarkd token revoke <名称>` 立即吊销。
- 请求方式：`Authorization: Bearer <token>`。只能 `GET` 四个接口：`/api/v1/bookmarks`（如 `?pinned=true&limit=12` 读取常用置顶）、`/api/v1/folders`、`/api/v1/tags`、`/api/v1/library/revision`；其余接口和任何写操作一律返回 401。
- 令牌与 Passkey 会话完全分开：不设置 Cookie，不能当作会话，也不满足「最近验证」。带 `Origin` 或 `Cookie` 头的 Bearer 请求会被拒绝，因此网页里无法使用令牌。
- 只保存令牌的摘要；所有摘要以常数时间比较；令牌不写入日志。请求与登录共用限流（每个来源每分钟 60 次）。
- 认证数据库新增一张表（仍为 auth schema 1，`CREATE TABLE IF NOT EXISTS`），与共享同一 `auth.db` 的旧版本程序兼容。`--include-auth` 备份不包含令牌，恢复后需重新创建。

升级：在「设置与迁移 → 版本与更新」中检查并安装；或下载对应平台的 `bookmarkd-*` 可执行文件，使用 `SHA256SUMS` 校验，备份数据后替换并重启。业务数据仍为 schema 1，不需要数据迁移。

此版本继续标记为预发布：尚未完成实机 Passkey 兼容性矩阵及独立安全审查。

## English

Adds read-only integration tokens so trusted server-side programs, such as a personal homepage, can read the library.

- Create a token on the server with `bookmarkd token create <name>`; it is printed once. `bookmarkd token list` shows names with creation and last-use times, and `bookmarkd token revoke <name>` revokes one immediately.
- Send `Authorization: Bearer <token>`. Only `GET` on four routes is allowed: `/api/v1/bookmarks` (for example `?pinned=true&limit=12` for pinned bookmarks), `/api/v1/folders`, `/api/v1/tags` and `/api/v1/library/revision`. Every other route and every write answers 401.
- Tokens are separate from Passkey sessions: no cookie, never a session, and never "recent authentication". Bearer requests that carry an `Origin` or `Cookie` header are refused, so tokens cannot be used from a web page.
- Only a digest of each token is stored, all digests are compared in constant time, and token values are never logged. Requests share the login rate limits (60 per minute per peer).
- The auth database gains one table (still auth schema 1, `CREATE TABLE IF NOT EXISTS`), so older hosts sharing the same `auth.db` keep working. Backups made with `--include-auth` leave tokens out; recreate them after restoring.

Upgrade from Settings → “版本与更新”, or download the matching `bookmarkd-*` executable, verify `SHA256SUMS`, back up your data, replace the executable, and restart. Storage remains schema 1; no data migration is required.

This remains a prerelease pending physical Passkey device coverage and independent security review.
